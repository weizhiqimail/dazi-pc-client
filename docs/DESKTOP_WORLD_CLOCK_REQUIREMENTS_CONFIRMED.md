# Windows 原生多时区时钟需求说明（确认版）

> 版本：1.0
>
> 状态：可进入第一版实现。
>
> 本文是第一版 Windows 原生时钟的产品规格与 Agent 实施指令。若与待确认稿冲突，以本文为准。

## 1. 已确认的产品目标

本仓库将演进为可以容纳多个独立桌面应用的仓库。第一版先实现一个真正采用 Windows 原生技术的多时区桌面时钟。

时钟是一个小型桌面挂件，不是网页式大窗口。它可以停靠在桌面左侧、右侧或顶部，能够锁定，并在 Windows 系统托盘显示图标和提供设置入口。

界面使用传统、朴素、紧凑、偏老式的 Windows 桌面程序风格。禁止使用现代卡片、圆角、毛玻璃、阴影、动效和现代 UI 组件库。

## 2. 仓库组织约束

### 2.1 多子项目结构

仓库根目录只承担项目集合、总览文档和通用仓库配置的职责，不作为某个 Node.js 应用的项目根目录。

目标结构：

```text
dazi-pc-client/
├─ apps/
│  ├─ world-clock-winforms/       # 第一版：.NET 8 WinForms 原生时钟
│  └─ dazi-toolkit-electron/      # 现有 Electron 工程（迁移后保留时）
├─ docs/                          # 跨项目需求和设计文档
├─ .gitignore
├─ LICENSE
└─ README.md                      # 仓库级项目索引，不承担具体应用构建
```

约束如下：

- 根目录不得使用一个 `package.json` 同时管理所有不同技术架构的子项目。
- Electron/Node.js 项目的 `package.json`、锁文件、TypeScript、Vite 和打包配置必须位于该 Electron 子项目内。
- .NET 原生项目使用自己的 `.sln`、`.csproj`、资源和发布配置。
- 不同技术架构的依赖、构建、测试和产物目录相互隔离。
- 只有同技术架构且确实需要共享依赖的项目，才可以在自己的技术栈目录内采用 workspace 或共享库；不得为了统一而跨技术栈耦合。
- 每个子项目必须有独立 README，说明开发、测试、构建和发布命令。
- 根目录 README 只列出子项目及其入口。
- 第一版原生时钟不得依赖根目录现有 Electron 依赖。

### 2.2 现有 Electron 工程处理

现有根目录是 Electron 工具箱骨架，包含 Markdown 和现代 UI 演示代码。正式整理仓库时应整体迁入独立 Electron 子项目，或在确认不再需要后删除。不得继续把它作为仓库根项目。

迁移现有 Electron 工程属于单独的仓库整理步骤。第一版原生时钟必须先在 `apps/world-clock-winforms/` 中独立建立，不复用 Electron 渲染层代码。

## 3. 第一版技术方案

- 操作系统：Windows 10 和 Windows 11。
- CPU 架构：x64。
- UI 技术：.NET 8 WinForms。
- 语言：C#。
- 时间来源：本机系统时间，不联网校时。
- 时区计算：使用 .NET `TimeZoneInfo` 和 Windows 时区标识，自动处理夏令时。
- 配置存储：应用本地 JSON 文件，存放在当前用户的 Local AppData 应用目录。
- 发布方式：独立的 Windows x64 发布包；具体采用单文件便携版还是安装包可在发布阶段决定，不影响核心实现。

选择 WinForms 的理由：

- 使用真正的 Windows 桌面控件和窗口消息机制。
- 视觉天然接近传统 Windows 程序。
- 系统托盘、菜单、对话框、窗口位置和消息处理成熟直接。
- 当前机器已安装 .NET 8 SDK 和 Windows Desktop Runtime，可以直接开发。

Moment 是 JavaScript 库，不用于 WinForms 子项目。`.NET TimeZoneInfo` 已能满足首批城市、当前时间和夏令时换算要求，第一版不额外引入时间库。

## 4. 城市与时区

第一版内置以下七个城市：

| 城市 | Windows 时区标识 | 标准时说明 |
| --- | --- | --- |
| 上海 | `China Standard Time` | UTC+08:00 |
| 东京 | `Tokyo Standard Time` | UTC+09:00 |
| 纽约 | `Eastern Standard Time` | 自动处理夏令时 |
| 芝加哥 | `Central Standard Time` | 自动处理夏令时 |
| 洛杉矶 | `Pacific Standard Time` | 自动处理夏令时 |
| 伦敦 | `GMT Standard Time` | 自动处理夏令时 |
| 巴黎 | `Romance Standard Time` | 自动处理夏令时 |

- 用户可以启用一个或多个城市。
- 至少保留一个启用城市。
- 用户可通过传统的“上移 / 下移”按钮调整顺序。
- 第一版不支持添加任意城市或自定义城市名称。
- 数据模型中的时差使用分钟表示，不假设永远是整数小时。

## 5. 时间显示

每个城市显示：

- 中文城市名。
- 当地日期，格式为 `yyyy-MM-dd`。
- 当地时间，格式为 `HH:mm:ss`，24 小时制。
- 相对基准城市的时差。

默认显示上海、东京、纽约，默认基准城市为上海。

相对时差文案规则：

- 基准城市显示“基准”。
- 比基准城市时间靠前显示“早 N 小时”。
- 比基准城市时间靠后显示“晚 N 小时”。
- 偏移量相同显示“相同时间”。
- 非整点时差显示为“N 小时 M 分钟”。
- 时差按两个城市在当前时刻的实际 UTC 偏移计算，必须正确响应夏令时变化。

中文“早/晚”容易产生语义歧义。实现和测试统一采用以下定义：当地墙上时间数值比基准城市大，显示“早”；数值比基准城市小，显示“晚”。例如上海 20:00、纽约 08:00，纽约显示“晚 12 小时”。

时间每秒刷新一次。跨日时日期必须同步更新，不能只更新时分秒。

## 6. 主时钟窗口

### 6.1 尺寸与布局

- 单个城市块以约 100×50 px 为紧凑目标，不是不可突破的硬限制。
- 优先保证城市、日期、时间和时差文字完整可读。
- 支持横向单行和纵向单列两种排列方式。
- 第一版不自动换行或分列。
- 切换城市数量、顺序或排列方向后，主窗口根据内容自动调整尺寸。
- 默认横向排列。
- 使用系统 DPI 感知能力，在 100%、125%、150% 等常见缩放下不裁切内容。

### 6.2 视觉

- 使用系统字体，优先 Segoe UI；不加载 Web Font。
- 浅灰背景、深灰文字、方形边框和传统分隔线。
- 使用 WinForms 标准控件或简单自绘，不引入第三方现代 UI 库。
- 不提供深色主题、透明度、动画和皮肤系统。
- 主窗口保持不透明。
- 设置窗口使用标准标题栏和传统对话框布局。

### 6.3 移动、停靠与锁定

- 窗口可自由拖动。
- 靠近当前显示器工作区的左侧、右侧或顶部时自动吸附。
- 默认首次出现在主显示器右侧。
- 第一版的“停靠”是边缘吸附，不注册 Windows AppBar，不占用系统工作区。
- 第一版不提供底部吸附，避免与 Windows 任务栏产生冲突。
- 记忆上次显示器、位置和吸附边。
- 显示器断开或分辨率变化后，窗口必须自动恢复到某个可见工作区内。
- 第一版不提供设置中的指定显示器下拉框；用户通过拖动选择显示器。

锁定后：

- 禁止鼠标拖动窗口。
- 禁止用户调整窗口尺寸。
- 不阻止时间显示、托盘操作或打开设置。
- 可从托盘菜单解锁，避免用户失去控制入口。
- 锁定状态持久化。

### 6.4 置顶与任务栏

- 提供“始终置顶”设置，默认关闭。
- 主时钟窗口不显示普通任务栏按钮。
- 应用运行时显示系统托盘图标。
- 第一版不专门检测游戏或视频全屏状态；置顶行为由用户设置决定。

## 7. 系统托盘与应用生命周期

应用保持单实例运行。重复启动时显示并激活已有的主时钟窗口。

托盘菜单包含：

- 显示/隐藏时钟。
- 设置。
- 锁定/解锁。
- 始终置顶开关。
- 退出。

行为规则：

- 单击托盘图标显示或激活主时钟窗口。
- 双击行为与单击一致，不另外定义命令。
- 关闭主时钟窗口时隐藏到托盘，不退出进程。
- 只有托盘菜单“退出”或设置界面中的明确退出操作才结束进程。
- 应用退出时释放托盘图标，避免通知区域残留无效图标。
- 第一版不提供开机启动；数据模型和菜单不预留不可用的假入口。

## 8. 设置窗口

设置使用独立的 WinForms 对话框，主时钟窗口保持显示。

设置内容：

1. 城市列表：复选框控制启用状态。
2. 城市排序：上移、下移按钮。
3. 基准城市：下拉框，仅列出已启用城市。
4. 排列方向：横向、纵向单选按钮。
5. 窗口行为：锁定位置、始终置顶复选框。
6. 恢复默认设置。

按钮使用传统的“确定 / 取消 / 应用”：

- “应用”保存并立即作用到主窗口，不关闭设置窗口。
- “确定”保存、应用并关闭设置窗口。
- “取消”丢弃自上次应用以来尚未保存的修改并关闭。
- “恢复默认”先更新对话框中的待应用值，用户仍需点击“应用”或“确定”。

设置窗口同时只能存在一个实例。再次点击设置时激活已有窗口。

## 9. 配置与容错

需要持久化：

- 已启用城市及顺序。
- 基准城市。
- 横向或纵向排列。
- 锁定状态。
- 始终置顶状态。
- 主窗口位置、所在显示器和吸附边。

配置要求：

- 包含配置结构版本号。
- 采用写临时文件后替换的方式，降低异常退出导致文件损坏的概率。
- 缺失字段使用默认值补齐。
- 无法解析、版本不兼容或内容非法时备份坏配置并恢复默认值。
- 基准城市被禁用时，自动选择启用列表中的第一个城市。
- 第一版不提供配置导入、导出或云同步。

## 10. 不在第一版范围内

- Markdown 编辑、预览或导出。
- 原 Electron 工具箱的导航页、控件页、动画页和反馈页。
- 天气、闹钟、秒表、倒计时、日历提醒。
- 网络校时。
- 添加任意时区或自定义城市。
- 透明窗口、深色主题、皮肤和动效。
- Windows AppBar 工作区占位。
- 开机启动。
- 自动更新。
- 多设备配置同步。
- macOS 或 Linux 支持。
- arm64 发布。

## 11. 验收标准

### 11.1 时间正确性

- 七个内置城市均能显示正确的当地日期和 24 小时时间。
- 秒钟连续更新，跨日后日期正确变化。
- 美国和欧洲城市在夏令时前后结果正确。
- 切换基准城市后，所有时差文案立即更新。
- 应用从系统睡眠恢复后，不依赖累计计时器，而是重新读取当前系统时间。

### 11.2 窗口能力

- 可以自由拖动并吸附到任一显示器工作区的左、右、顶部。
- 锁定后不能通过普通鼠标操作移动或缩放。
- 可以从托盘解锁。
- 横向和纵向布局不会裁切文本。
- DPI、分辨率或显示器变化后窗口保持可见。
- 始终置顶设置实时生效并在重启后保留。

### 11.3 托盘与生命周期

- 应用运行期间托盘图标始终可用。
- 主窗口关闭后应用继续运行，并能从托盘重新显示。
- 托盘菜单可以打开设置、锁定、切换置顶和退出。
- 重复启动不会出现第二个时钟实例。

### 11.4 配置

- 可以启用、停用、排序城市并选择有效基准城市。
- 至少保留一个城市。
- “确定 / 取消 / 应用 / 恢复默认”行为符合第 8 节。
- 重启应用后设置和窗口位置恢复。
- 配置损坏不会阻止应用启动。

### 11.5 工程质量

- 原生时钟位于独立子项目，不引用根目录 Node.js 依赖。
- 可通过 `dotnet build` 和自动化测试。
- 核心时区换算、相对时差、配置校验和窗口可见区域修正具有单元测试。
- 发布的 Windows x64 应用可在未安装开发工具的干净环境运行。
- 最终进行 Windows 10/11、系统托盘、多显示器和 DPI 的人工验收。

## 12. Agent 实施顺序

1. 创建 `apps/world-clock-winforms/` 独立解决方案、应用项目和测试项目。
2. 实现城市目录、时区换算和相对时差纯逻辑及测试。
3. 实现带版本的配置模型、校验、原子保存和测试。
4. 实现紧凑主时钟窗口与横向/纵向布局。
5. 实现设置对话框。
6. 实现托盘菜单、单实例和关闭到托盘。
7. 实现窗口吸附、锁定、置顶、多显示器恢复和 DPI 适配。
8. 添加应用图标和发布配置。
9. 完成自动化检查及 Windows 实机验收。
10. 原生时钟稳定后，再将根目录现有 Electron 工程迁入独立子项目；迁移时不得混入原生时钟的功能修改。

实施中继续保持最小权限和明确边界：不要引入 WebView、Electron、Node.js 或第三方 UI 框架；不要为未列入第一版的功能预埋可见入口。
